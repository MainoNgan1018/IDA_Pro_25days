- Reload the input file: nạp lại dữ liệu từ chính game.exe gốc vào database hiện tại. Thường dùng khi file trên ổ đĩa đã thay đổi hoặc bạn muốn phục hồi byte từ file gốc.
- Additional binary file...: nạp thêm một file binary vào database hiện tại và đặt nó vào một vùng địa chỉ bạn chọn. Hữu ích với firmware/ROM hoặc chương trình gồm nhiều blob; với game.exe CTF bình thường thì gần như không cần.
- IDS/IDT file...: nạp thông tin kiểu/type và symbol từ các file IDS/IDT của IDA. Ít dùng trong reverse EXE thông thường.
- PDB file...: rất đáng chú ý khi reverse Windows. PDB là Program Database do Visual Studio/MSVC tạo ra, có thể chứa tên hàm, type, source information... Nếu challenge vô tình cung cấp/còn PDB phù hợp thì việc reverse có thể dễ hơn rất nhiều.
- DBG file...: nạp debug information ở định dạng DBG cũ của Windows/Microsoft.
- TDS file...: debug symbol format của Borland/Embarcadero (Turbo Debugger). Không liên quan nếu chương trình được build bằng MSVC/GCC bình thường.
- FLIRT signature file...: nạp signature để IDA nhận diện các hàm thư viện. Ví dụ thay vì thấy một sub_1400xxxxx vô danh, signature phù hợp có thể giúp IDA biết đó là hàm thư viện nào.
- Parse C header file... (Ctrl+F9): cái bạn đang trỏ chuột vào. Nó cho IDA đọc file header C (.h) để import struct, typedef, enum, prototype....
Ví dụ bạn có:
```
struct Player {
    int hp;
    int score;
    int round;
};

struct GameState {
    Player player;
    int level;
};
```
Bạn có thể cho IDA parse header chứa các struct này. Sau đó khi reverse, thay vì phải tự nhớ kiểu:
```
[a1+2830h]
[a1+2834h]
```
bạn có thể áp kiểu dữ liệu phù hợp để pseudocode trở nên dễ đọc hơn, kiểu như:
```
state->round
state->player.hp
```
